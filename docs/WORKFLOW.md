# Story workshop workflow

Use one story ID and a separate session ID for every run or branch. Import a private workshop JSON file or start a new story. The website does not connect to your accounts or generate fiction through an AI service.

## Before play

Record the premise, intended experience, calendar, latest checkpoint, current resources, injuries and pending obligations. Keep character names under stable IDs. Select one branch.

## During play

State one intent, attempted action, constraint and stop point. Resolve actual outcomes independently. Record completed events with evidence references. Keep proposals, predictions and suspicions outside the completed event record.

## After play

Record resource acquisitions and spending, time elapsed, location changes, ability demonstrations, relationship changes and commitments. A higher maximum does not heal the current resource. A plan does not establish completion. An NPC's fear does not establish loyalty.

## Repair and test

For each conflict, preserve both source claims. Propose the smallest repair, record approval in a retcon, then rerun affected tests. Record actual observations, tester and version. A defined test is not a completed test. Structured checks cover only entered records and do not establish that unrecorded history is correct.

## Save

Save explicitly on the device and export portable JSON backups. Device storage can be cleared. Keep private backups in private storage with appropriate access. The app has no cloud synchronization, encryption service or recovery account.

## Release

Review rights, assets, audience, actual tests and unresolved findings. Public export permits only approved titles and synopses. Publish the `site/` shell on GitHub Pages; do not publish private packages, imported histories, personal guides or the whole workshop ZIP. Check staged files before committing. Ignore rules do not protect manually uploaded or previously tracked files.
